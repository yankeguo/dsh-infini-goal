# v0.2.1 — staged 发布流水线 + 插件展示元数据

本版本有两项主题：**发布流程改为 npm staged publish**（CI 只暂存、维护者 2FA 审批后才公开），
以及 **8 个包补齐中英文插件展示元数据**（Plugins 页面/插件市场显示友好名称与一句话描述）。
功能行为与 0.2.0 一致，升级无需改动配置。

## 发布流水线：staged publish（不再由 CI 直接发布）

- **CI 只 stage**：推 `v*` tag 后，[`.github/workflows/publish.yml`](../.github/workflows/publish.yml)
  依次做 tag/版本门禁 → install → typecheck → test → build → 按依赖拓扑逐个
  `pnpm stage publish`。stage 不需要 2FA，但上传的版本处于**私有暂存区**，用户不可安装；
  工作流没有任何 npm token secret（仅 `id-token: write`），**不再创建 GitHub Release**。
- **人工 2FA 审批**：维护者在本机审查暂存结果并逐包 approve（`npm stage approve`，每个包一次
  一次性密码），全部成功后才公开，并由审批脚本用 `docs/releases/v<version>.md` 创建 GitHub
  Release。未 approve 前任何失败都不会造成「部分包已公开」的半发布。
- **trusted publisher 迁移**：trust 配置从旧的 `--allow-publish` 迁移为只允许
  `--allow-stage-publish`（CI 无法直接公开版本）。`scripts/trusted-publishers.sh` 新增
  `--migrate`（revoke 旧配置并重建 stage-only）与 `--list`（逐包校验权限必须是
  `permissions: stage publish`）。
- **新增脚本**：
  - `scripts/stage-release.mjs`：校验 8 包 + 根版本与 `v<version>` tag 一致、按 workspace
    依赖拓扑排序、构建产物预检，逐包 `pnpm stage publish --access public --tag <dist-tag>
    --provenance`；支持 `--gate` / `--check` / `--dry-run`，失败时输出 reject/重跑/升版本恢复指引。
    使用 pnpm 而非 npm 执行 stage：npm 打包会原样保留 `workspace:*`，pnpm 会改写为精确版本。
  - `scripts/promote-release.mjs`：按版本列出暂存 stage-id、校验 8 包齐全且 dist-tag 一致，
    逐包 approve（2FA 交互）→ `npm view` 验证已公开 → `gh release create`；支持
    `--list-only` / `--dry-run` / `--reject` / `--no-github-release`，并可重跑以继续部分失败的
    approve（已公开的包自动跳过）。
- **重新 stage 入口**：`workflow_dispatch` 新增 `release_tag` 输入与 `dry_run` 开关；可对
  **已存在的 tag 重跑**（checkout 该 tag，不移动 tag、不改历史），代码修复必须升新版本。
- **dist-tag 策略**：稳定版 `latest`；预发布版本（`-rc.N` 等）自动使用 `next`，避免预发布
  顶掉 `latest`。
- 根 `package.json` 脚本：移除直接发布的 `release:publish` / `release:dry`，新增
  `release:check` / `release:stage` / `release:stage:dry` / `release:promote`。
- 文档：[`docs/PUBLISHING.md`](../PUBLISHING.md) 重写为 stage → 审查 → approve → GitHub Release
  的完整流程，包含 trust 迁移、失败恢复矩阵与安全模型；`README` 中英同步更新。

## 插件展示元数据（8 个包，中英双语）

- 每个包新增 `locale/en.json` + `locale/zh.json`（`{"meta":{"title","description"}}`），
  `package.json` 的 `files` 增加 `locale/*.json`、`exports` 增加 `"./locale/*.json"`，
  `description` 与英文 locale 同步（DSH 缺字段时的回退文案不会漂移）。
- DSH 不执行插件代码即可读取这些文件，Plugins 页面与插件市场因此显示友好名称而非 npm 包名；
  已有 `icon`（两个 bundle）保持不变。

| 包 | 英文展示 | 中文展示 |
| --- | --- | --- |
| `protocol` | Infini Goal Protocol | 无限目标协议层 |
| `infini-goal` | Infini Goal | 无限目标 |
| `driver` | Infini Goal Driver | 无限目标驱动器 |
| `tool` | Infini Goal Tools | 无限目标工具 |
| `command` | Infini Goal Command | 无限目标命令 |
| `client-ui` | Infini Goal Status Bar | 无限目标状态栏 |
| `bundle` | Infini Goal | 无限目标 |
| `disable-goal-bundle` | Disable Built-in Goal | 关闭系统自带目标 |

- 新增 `packages/bundle/tests/plugin-metadata.spec.ts`：校验 8 包 locale 文件存在、JSON 合法、
  中英 title/description 非空、`files`/`exports` 接线正确、`description` 与英文 locale 同步、
  标题不暴露技术包名、描述不含营销最高级词；新增包漏配会被测试拦下。

## 兼容性

- DeepSeek Harness：`>=0.2.2-rc.1 <0.3.0`（`engines.dsh`，8 个包均声明）
- Node.js：`>=24.9`（构建/发布工具链）
- 维护者发布工具链：pnpm 12（CI 固定 `pnpm@12.16.1`）、npm ≥ 11.20.0（`npm stage` 审批）、
  已认证的 `gh`（创建 GitHub Release）

## 升级 / 安装

```sh
# npm（本版本 approve 公开后）
dsh plugin --profile desktop add @yankeguo/dsh-infini-goal-bundle@0.2.1

# 本地 checkout
pnpm install && pnpm build && pnpm install:profile
```

本次发布本身即首次以 staged 流程发布：CI 完成 8/8 stage 后，由维护者 `npm login`（2FA）
运行 `node scripts/promote-release.mjs --version 0.2.1` approve 并创建 GitHub Release。
