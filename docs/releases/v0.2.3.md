# v0.2.3 — 授权收紧与 DSH 0.2.2-rc.1–rc.5 兼容性

本版本收紧 infini-goal 模型工具的授权来源，移除插件特定的委托授权机制，并把
DSH `0.2.2-rc.1` – `0.2.2-rc.5` 的兼容性验证补齐为真实矩阵。8 个发布包统一升到
0.2.3；目标持久化表示与配置格式不变，升级无需迁移数据。

## 变化

### 授权收紧

- 移除了插件特定的委托授权 opt-in 及其配置键。模型工具不再识别任何第三方插件
  的消息来源；`create_infini_goal` 与 `update_infini_goal` 的 `edit` / `config` /
  `resume` 只接受顶层 runtime root 当前 turn 的直接人类消息。
- `pause` / `complete` / `blocked` 额外允许“当前目标的 exact automatic round”授权。
  其中 `pause` 只停止自主续跑、不能创建或改写目标，因此首次允许在自动轮次内调用；
  `blocked` 在自动轮次下仍受 `blockedAfterConsecutiveRounds` 限制。
- 定时任务、subagent、agent-team、其他 agent 消息和运行期通知永不授权目标变更。
  由这些来源开启的 turn 即使文本看起来像用户请求，也不能 create/edit/config/resume；
  这是有意的 fail-closed 行为，文档已说明。
- 错误信息仍保留 `INFINI_GOAL_TOOL_AUTHORITY_REQUIRED`，并说明仍被拒绝的来源。

### DSH 兼容性

- 在 npm 独立安装的 `0.2.2-rc.1`、`rc.2`、`rc.3`、`rc.4`、`rc.5` 上分别做真实隔离验证；
  每个版本均通过 suite、模型工具、安装路径与 bundle 回归。
- rc.1 的 `AgentRegistry.roots()` / `waitForChildren()` 与 rc.2+ 的
  `session.header.origin` + `delegationDepth` / `waitForTreeWork()` 由既有
  feature-detect 兼容层处理；rc.4 仅新增 `dsh-llm` 的 `CONTENT_REFUSED` 失败码；rc.5 的变更集中在 web search
  路由，本套件不依赖这些包，goal/driver 链路实测不受影响。
- `engines.dsh` 与宿主 peer 仍为 `>=0.2.2-rc.1 <0.3.0`，覆盖四个 rc 版本。

### E2E

- `tools/e2e/probe-tools.sh` 现在在一次运行中验证工具注册、system prompt 授权文本、
  `create_infini_goal` 和 `update_infini_goal`（action `edit`）四个层面；mock LLM
  新增运行时替换场景的测试端点。

## 升级 / 安装

```sh
# npm（本版本 approve 公开后）
dsh plugin --profile desktop add @yankeguo/dsh-infini-goal-bundle@0.2.3

# 本地 checkout
pnpm install && pnpm build && pnpm install:profile
```

更新后需要**重启 DSH**（host 插件与 preset 行在启动时绑定），并刷新 Web 页面；无需迁移
目标数据。
