# v0.2.2 — DSH 0.2.2-rc.3 兼容性修复

本版本只修复 DeepSeek Harness（DSH）**0.2.2-rc.3** 上的插件 API 兼容性，不改变 infini-goal
的功能语义、持久化表示或配置格式；升级无需迁移数据。8 个发布包统一升到 0.2.2。

## 问题

在安装版 DSH 0.2.2-rc.3 上，模型工具的直接人类授权路径会直接抛错：

```text
Error: ctx.agents.roots is not a function
```

受影响的是 `create_infini_goal` 与 `update_infini_goal` 的 edit / pause / resume / complete /
block（都要求 direct-human 授权）。另外：

- 驱动器在子代理运行后预留自动轮次时调用已被移除的 `subagents.waitForChildren()`；
- 用 0.2.2-rc.1 SDK 的 `zod@4.4.3` 对 rc.3 做类型检查会报 `TS2739`（projection schema 缺少
  `validate` / `validateAsync`）与 `TS2589`（类型实例化过深）。

## 修复

| 变化（DSH 0.2.2-rc.2+） | 兼容处理 |
| --- | --- |
| `AgentRegistry.roots()` 被移除 | `isRuntimeRoot()` 在存在 `roots()` 时沿用 rc.1 语义，否则要求 exact live agent 且 `session.header.origin !== 'subagent'`，与 rc.3 官方 `dsh-tool-goal` 的授权判定一致 |
| `SubagentsService.waitForChildren(parent)` 改名为 `waitForTreeWork(root)` | 驱动器优先调用旧方法，回退到新方法；两者都没有时视为无需等待 |
| projection schema 与 rc.3 内置 `zod@4.6.6` 的类型身份绑定 | 仓库 devDependency 与核心包 `zod` peer 统一为 `4.6.6` |

依赖声明同步：根 devDependencies 与 `disable-goal-bundle` 的 `@deepseek-ai/dsh-agent-preset`
devDependency 升到 `0.2.2-rc.3`；8 个包的宿主 peer `@deepseek-ai/dsh-*` 由精确 `0.2.2-rc.1`
改为声明范围 `>=0.2.2-rc.1 <0.3.0`（`engines.dsh` 原本就是该范围）。详细矩阵与后续升级步骤见
[DSH 兼容性](../COMPATIBILITY.md)。

## 兼容性

- DeepSeek Harness：`>=0.2.2-rc.1 <0.3.0`（`engines.dsh`，8 个包均声明）；已在 0.2.2-rc.1
  （历史版本）与 0.2.2-rc.3（本版本）验证。
- Node.js：`>=24.9`（构建/发布工具链）；从 npm 安装插件不需要本机 Node。
- 维护者工具链：pnpm 12、npm ≥ 11.20.0（`npm stage` 审批）、已认证的 `gh`。

## 升级 / 安装

```sh
# npm（本版本 approve 公开后）
dsh plugin --profile desktop add @yankeguo/dsh-infini-goal-bundle@0.2.2

# 本地 checkout
pnpm install && pnpm build && pnpm install:profile
```

更新后需要**重启 DSH**（host 插件与 preset 行在启动时绑定），并刷新 Web 页面；无需迁移目标数据。
