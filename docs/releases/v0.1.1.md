# v0.1.1 — 审计修复版（会话持久化、driver 竞态、仓库完整性）

本版本是对 0.1.0 的全面审计修复，**包含两个数据/可用性级别的 P0 修复**，升级前请先读
「升级与旧会话修复」。功能面（无轮次上限、最小触发间隔、静默时段）保持不变。

## P0 修复

- **会话重启不可恢复（数据丢失）**：0.1.0 把目标变更写成自定义 Session 事件
  `infini-goal/change`。DSH 0.2.2-rc.1 的持久化读取（`validateStoredEvents`）只接受内置词表内
  的 event type（或带 `ignorable` 标记的插件记录），因此**任何创建过目标的 Session 重启后都会
  被拒绝解释**（`refusing to interpret the log — it was likely written by a newer harness`）。
  现在改用 DSH 官方插件状态通道：可忽略的 `plugin:infini-goal/change` 插件记录
  （`appendPluginRecord`），payload 形状不变，resume / fork / transport 都会保留；
  严格 fold 仍只读兼容退役的旧事件类型（用于热重载），永不写入。projection `stateVersion` 1 → 2。
- **driver：block/pause 永不持久化**：从 `session/event` 观察者里写入目标变更会触发
  "session append cannot reenter" 异常且被吞掉，导致 `max-tokens` / turn error / aborted
  之后目标仍为 `active` 并立即再跑一轮。现在目标变更延迟一个 microtask 并做 revision fence。
- **driver：卸载泄漏自动轮消息**：插件卸载时未撤回已排队未准入的 round 消息，之后会被当成
  普通用户消息执行（可能让严格 fold 永久失败）。现在在 unload / agent-created / idle / pause /
  stale 路径全部撤回。
- **仓库完整性**：根 `.gitignore` 的 `lib/` 规则未锚定，导致 `scripts/lib/disable-goal.mjs`、
  `tools/e2e/lib/{common.sh,web-client.mjs}`、`packages/disable-goal-bundle/lib/preset-filter.js`
  从未入库——干净 clone 下安装脚本、e2e、关闭官方 goal 的 bundle 全部不可用。现已修复规则、
  补齐文件，并把 preset-filter 纳入 `pnpm build`（`src/preset-filter.js` 复制为 `lib/` 资产）。

## 其他修复（P1/P2）

- **静默时段显示**：`planTrigger` 之前把"未来静默窗口推迟了间隔候选"误报为
  `reason: 'interval'`、`quietUntil: null`，UI 会整段显示"最小间隔"而不是"静默时段 · 至 HH:mm"。
  新契约：`quietUntil === nextAt`、`reason: 'quiet-window'`。
- **DST 回拨日**：静默窗口边界改为"起点取最早、终点取最晚"的保守解析，避免不同时区在
  fall-back 日判定不一致。
- **driver 行为**：turn 结果按自动轮自身的 turn 归因（人类 turn 的 max-tokens/error/aborted
  不再误 block/pause 目标）；子代理等待后重新检查 pacing（不再于静默窗口内注入轮次）；
  checkpoint 失败改为 `checkpoint-failed` block（不再无限重试）；串行 driver 重入 fence。
- **protocol 解析**：时长/静默窗口/星期/时区校验硬化；全时段覆盖的静默配置快速拒绝
  （11.5ms → 0.8ms）；`canonicalTimeZone` 拒绝 `±offset` 时区 id。
- **命令**：支持成对引号参数（README 示例 `/infini-goal quiet "Mo-Fr 09:00-18:00"` 之前会失败）；
  `interval` / `quiet` / `timezone` 在 `complete` 目标上给出明确拒绝。
- **工具**：空白 `quiet_windows` 不再被静默当作 `none`；`blocked` 阈值语义与错误码文档对齐。
- **状态条 UI**：Host 命令的逻辑拒绝（`ok:true` + `Kind:'error'`）不再被吞掉；
  projection 变化时倒计时立即刷新；HMR 复用样式标签时刷新 CSS。
- **安装/构建/CI**：`install-profile.mjs` 幂等、校验构建产物、`--uninstall` 清理生成的 patch 块；
  `build.mjs` 缺少入口时硬失败并支持 `--only`；`dev-patch.mjs` 输出 YAML 安全引号；
  `publish.yml` 增加 tag↔版本一致性门禁并固定 action 版本；vitest 别名路径用 `fileURLToPath`。
- **文档**：README / DESIGN / DISABLE-BUILTIN-GOAL / PUBLISHING / bundle README / e2e README
  全量同步（事件表示、静默时段语义、错误码、权限模型、构建产物、验证证据、故障排查）。

## 升级与旧会话修复

0.1.0 写出的旧 Session **不会自动迁移**，升级后如果发现某个 Session 重启时无法恢复
（日志报 "refusing to interpret the log"），请先退出所有 DSH 实例，然后运行：

```sh
node scripts/repair-session-log.mjs --dry-run --dsh-home ~/.dsh   # 只打印将修复的行
node scripts/repair-session-log.mjs --write  --dsh-home ~/.dsh    # 写入（带时间戳备份）
```

脚本只把 `infini-goal/change` 行改写为 `plugin:infini-goal/change` + `ignorable: true`，
其余行与字节保持不变，默认拒绝修复仍被 DSH 打开的 Session（`session.lock`，确认属主进程已退出
可加 `--force`），重复执行幂等。详见 README「从 0.1.0 升级 / 修复旧会话」。
